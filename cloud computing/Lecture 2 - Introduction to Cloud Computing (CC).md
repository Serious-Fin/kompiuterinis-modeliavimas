Cloud Computing is OSSM:
- O - On-Demand
- S - Self-Service
- S - Scalable
- M - Measurable (cost is known up-front)

Google's view to Cloud Computing:
- Oriented to customer - data belongs to customer
- Oriented to test - particular tasks, not programs. User just buys the tools (storage, compute, etc.) to perform something
- Powerful - user should be able to perform the task
- Accessible - reachable from anywhere
- Intelligent
- Automized (from user experience, to the data centers, everything is automized)

Cloud computing features:
- Variable scale resources and services
- Resources and services accessible via internet (or using private cloud) - anybody can reach from any of their devices
- Payed according to used resources
- There should be no expenses in order to start using services

Essential features according to NIST
- Self service according to needs
- Ubiquitous network access
- Resource accumulation
- Independence from location
- Quick scalability
- Measurable service

Open Cloud Manifesto principles:
- **User centric** - users are the ones who should build services, so providers bring the tools to the users and make then accessible.
- **Philanthropic** initiatives don't work.
- **Openness** of standards - systems and software empowers and protects software students.
- **Transparency** fosters trust and accountability. This brings in more users.
- **Interoperability** ensures effectiveness
- **Representation** of all stakeholders is essential
- **Discrimination** is unacceptable. Service should be reachable from all countries.
- **Evolution** is an ongoing process
- **Balance** of commercials and consumers interests is paramount.
- **Security** is fundamental, not optional

So why is cloud manifesto important? It's because:
- Scalability on demand
- Streamlining the data centers
- Improving business processes

Challenges and barriers for adoption:
- Security
- Data and application interoperability
- Data and application portability
- Governance and management
- Metering and monitoring

Goals of open cloud:
- Choice - users should be able to choose whatever, whenever.
- Flexibility
- Speed and agility - users adapt faster and do more.
- Skills - developers get used to a system and prefer to use that platform for their projects.
